# Архитектура

```
Telegram ──(WebApp, initData)──► apps/web (React SPA)
   │                                   │  Authorization: tma <initData>
   │ webhook/polling                   ▼
   └──────────────────────────► apps/api (Fastify) ──► PostgreSQL (Prisma)
                                   │  ├─ apps/bot (grammY, встроен в API)
                                   │  └─ Bot API getChatMember (подписка), sendMessage (напоминания)
```

В production один процесс раздаёт и SPA, и `/api`, и `/telegram/webhook` — один домен, без CORS.

## Аутентификация

1. Клиент берёт `Telegram.WebApp.initData` и шлёт его в каждом запросе: `Authorization: tma <initData>`.
2. Сервер (`apps/api/src/telegram/init-data.ts`) пересчитывает HMAC-SHA256 по алгоритму Telegram (`secret = HMAC("WebAppData", BOT_TOKEN)`), сравнивает в постоянное время, проверяет `auth_date` (по умолчанию 24 ч).
3. Только после этого `user.id` используется: пользователь создаётся/обновляется по `telegramId`. Любой ID, присланный клиентом иначе, игнорируется.
4. `DEV_AUTH_BYPASS` — тестовый пользователь для браузера; в production сервер не стартует с этим флагом.

## Учебная логика (серверная)

- Клиент получает вопросы **без** `isCorrect`. Ответ (`POST /api/answers`) проверяется по БД.
- `clientAttemptId` (UUID) + уникальный индекс `(userId, clientAttemptId)` — повторная отправка возвращает сохранённый результат.
- XP начисляется только через журнал `XpEvent` с уникальным `dedupeKey` (`first-correct:<q>`, `mistake-fixed:<q>`, `ticket:<id>`, `daily:<день>`, `exam-passed:<день>`, `achievement:<code>`), вставка `ON CONFLICT DO NOTHING`. Повтор вопроса не даёт бесконечных наград.
- Ранги и баланс XP — данные (таблица `Rank`, `AppSettings["xp"]`), меняются в админке.
- «Мои ошибки» — таблица `Mistake`; верный ответ закрывает ошибку, в режиме ошибок даёт бонус один раз.
- Прогресс хранится на сервере → продолжение на другом устройстве. Позиция внутри сессии дополнительно сохраняется в `sessionStorage` (переживает обновление страницы).

## Экзамен

`packages/shared/src/exam.ts` — чистые функции (покрыты тестами):
- `gibdd-abm`: 4 блока × 5 вопросов, 20 мин; ≤ 2 ошибок в разных блоках; за ошибку +5 вопросов того же блока и +5 мин; ошибка в доп. вопросах, 2 ошибки в блоке или > 2 ошибок — не сдано.
- Блок вопроса = `Topic.examBlock`. Для официальных билетов можно назначить блоки по позиции в билете (1–5, 6–10, …) — достаточно разложить вопросы по 4 темам-блокам.
- Ответ в экзамене фиксируется и не меняется; правильность и объяснения раскрываются после завершения.

## Обязательная подписка

`apps/api/src/services/subscription.ts`:
- Источники — таблица `RequiredSubscription` (chatId не уходит клиенту), флаг — `AppSettings["subscription"]`.
- Флаг выключен или нет активных источников → проверок нет вообще.
- `POST /api/gate/check` — живая проверка `getChatMember` для каждого источника; результат в `SubscriptionCheck`, успешный действует `SUBSCRIPTION_TTL_MIN`.
- Все учебные маршруты защищены `assertAccess` (preHandler). Статус от клиента не принимается.
- Временный сбой Telegram: пользователь с успешной проверкой за `SUBSCRIPTION_GRACE_HOURS` проходит; остальные получают `503 SUBSCRIPTION_CHECK_UNAVAILABLE` и кнопку повтора. Провал из-за сбоя не записывается.
- Ошибки конфигурации (бот не в чате и т.п.) пишутся только в лог сервера.

## Безопасность

- Секреты только в `.env`; клиентская сборка не содержит токенов.
- zod-валидация всех входных данных, общий обработчик ошибок без внутренних деталей.
- Rate limit: глобально 240/мин на пользователя (ключ — хэш initData), строже на проверку подписки, помощника и жалобы.
- Helmet + CSP; фреймы разрешены только Telegram Web (`frame-ancestors`).
- Админ-API: Telegram ID из `ADMIN_TELEGRAM_IDS` или `X-Admin-Token` (сравнение в постоянное время). Скрытая страница не является защитой — права проверяются на каждом маршруте.
- Загрузка изображений: только PNG/JPEG/WebP по сигнатуре, до 2 МБ, раздаются с `CSP: sandbox` и `nosniff`.

## Дизайн-система

Токены — `apps/web/src/styles.css` (`@theme`): палитра (`--color-pink #FF2F91`, `--color-pink-soft #FFE0EF`, `--color-pink-50 #FFF0F7`, `--color-ink #24232B`, `--color-gold #FFD34E`, ok/bad), радиусы карточек/плиток, тени, шрифт Nunito (кириллица, локально через @fontsource), анимации. Компоненты — `apps/web/src/components/ui.tsx`. Фирменные ассеты — `apps/web/public/brand` (вырезаны из присланных концептов). Знаки (`public/signs`) и схемы ситуаций (`public/scenes`) генерируются скриптами и намеренно не стилизуются «под мультяшку».

## Голос «Заюша»

Словарь — `packages/shared/src/voice.ts` (несколько вариантов на ключ, выбор случайный). Переопределения хранятся в `AppSettings["texts"]` и редактируются в админке. Экзамен использует сдержанные формулировки.
